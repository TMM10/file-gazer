# File Gazer local API

The portable `FileGazer.exe` uses the installed Windows .NET Framework 4.x and listens only on `127.0.0.1`. It tries port 47831, then 47832–47850, then an available port. `backend/server.port` records the current port. A named mutex ensures one normal process per app directory; launching the executable again opens the existing service. Normal launch shows the embedded File Gazer star icon in the Windows notification area, with **Open File Gazer** and **Exit**. The same icon is embedded in the executable for Windows shortcuts. `--no-browser` suppresses the browser and tray for automated checks. `--port=47841` creates a separate isolated test service with its own mutex and `backend/server-47841.port`; it never replaces a normal service's inventory.

All inventory data is held in memory. Scans do not change the scanned filesystem; explicit rename and Recycle Bin actions change only selected scanned items. The scanner uses Unicode Win32 enumeration, including extended-length paths, skips reparse-point files and directories, and reports inaccessible or skipped items. File contents are not read except bounded Steam `.acf`/library metadata and Epic `.item` launcher metadata, up to 1 MiB per metadata file. Totals describe logical file bytes, not allocated disk blocks. Hard-linked files are counted per directory entry; inaccessible files, reparse points, filesystem metadata, compressed/sparse allocation differences, and system-reserved disk usage can make totals differ from used drive capacity.

Requests must use the exact Host `127.0.0.1:PORT`; an Origin must equal `http://127.0.0.1:PORT`, and cross-site browser fetches are rejected. No CORS access is granted. JSON errors use `{ "error": "message" }` with an appropriate non-2xx status. Bodies are limited to 1 MiB. There is no permanent-delete, arbitrary shell-command, arbitrary destination move, or file-content editing API.

| Method | Path | Behavior |
|---|---|---|
| GET | `/api/health` | `{app:"StorageAtlas",product:"File Gazer",instance,port,version:"1.1"}`; legacy app identifier retained for compatibility |
| GET | `/api/drives` | `{drives:[{path,name,total,free,type}]}` for ready Windows drives |
| POST | `/api/scan` | JSON `{paths:[absolute folder or drive paths]}`; returns `{id}`; unavailable/reparse roots reject the entire request before replacing inventory; overlapping roots are deduplicated; a running scan returns 409 |
| POST | `/api/cancel` | Requests cancellation and returns current status; poll status until terminal |
| GET | `/api/status` | `{id,revision,state,files,folders,bytes,currentPath,errors,startedAt,finishedAt}`; states `idle`, `running`, `complete`, `cancelled`, `error`; timestamps UTC ISO 8601 |
| GET | `/api/overview` | `{roots,size,files,folders,categories,games,gameLibraries,inactiveGameLibraries,extensions,warnings,warningCount,state,id,revision,sizeBasis,reparsePointsSkipped}` |
| GET | `/api/node?path=...` | Folder details and immediate children; omit/empty `path` for synthetic all-scanned-locations root |
| GET | `/api/search?q=...` | `{items,total,offset,limit,state}`; substring matches name or full path |
| POST | `/api/reveal` | JSON `{path}`; opens Explorer selecting a scanned item; rejects paths absent from inventory |
| POST | `/api/open` | JSON `{path}`; opens a scanned regular file using its Windows association; executable/script/installer/shortcut types are blocked; returns `{opened:true}` |
| POST | `/api/properties` | JSON `{path}`; shows native Windows properties for a scanned item; returns `{opened:true}` |
| POST | `/api/steam-library` | JSON `{path}` only; opens a recognized scanned Steam game's library page using Windows' Steam protocol association; returns `{opened:true,steamAppId}`; does not start the game |
| POST | `/api/game-library` | JSON `{path,enabled:boolean}`; marks or unmarks an exact scanned folder as a saved game library; returns `{path,enabled,revision,overview}` |
| POST | `/api/rename` | JSON `{path,name}`; renames one basename without overwriting; returns `{renamed:true,path:newPath,oldPath,revision,overview}` |
| POST | `/api/recycle` | JSON `{path}` or `{paths:[...]}` up to 200; returns `{results:[{path,success,error}],recycled:[paths],errors:[{path,error}],revision,overview}`; moves successful items to the Recycle Bin only |
| GET | `/api/export` | Downloadable JSON hierarchy with `schemaVersion:1`, `sizeBasis`, `scan`, `categories`, `games`, `extensions`, `warnings`, and recursive `roots[].children` |

Common item fields are `{path,name,kind,size,fileCount,folderCount,category,extension,parent}`. `kind` is `folder` or `file`. Folder `category` and `extension` are null. File `extension` is a lowercase dot-prefixed extension, or `(none)`. Folder file/folder counts exclude the folder itself; global status folder counts include scan roots. Synthetic-root and scan-root `parent` is an empty string.

`/api/node` also returns `{children,totalChildren,childrenSizeTotal,remainingSize,offset,limit,state,revision}`. Search also includes `revision`. Children are sorted by logical size descending, then by name. The default limit is 500, maximum 5000, and `offset` supports pagination. `childrenSizeTotal` includes every matching child, including children beyond the current page. `remainingSize` includes every matching child at or after the requested offset, including entries beyond the page limit; it is zero once the offset reaches the end. It provides the exact area total when navigating the remaining items of a very large folder. The node's own size equals `childrenSizeTotal` for folders. Empty folders and zero-byte files remain available in the unfiltered inventory.

Both node and search accept a case-insensitive `category` from **Games, Applications, System, Videos, Images, Audio, Documents, Archives, Code, Other**. Filtering retains ancestors with matching descendant files, and reports matching bytes/file counts. Search also supports exact `extension=.mp4` and `path=...` subtree scope. `(none)` or `[no extension]` finds files without an extension. Search defaults to 100 results, maximum 5000, with pagination up to offset 1,000,000.

Category totals are mutually exclusive. Known game roots take priority; system/program directories then classify their descendants; loose files use extensions, followed by Other. Game discovery uses installed Steam library/app manifests and Epic launcher manifests. Scanning a `steamapps` directory discovers manifests there before scanning games. Folder children of `steamapps/common`, `Epic Games` (except Launcher), `XboxGames`, and `GOG Games` use a labeled fallback. Starting directly inside one of those layouts also recognizes its game ancestor, including adjacent Steam manifests. Game rows include `{name,path,installationPath,size,source,files}` with source `Steam manifest`, `Epic manifest`, or `Known game folder`. A Steam row additionally includes optional `steamAppId`, a canonical positive uint32 decimal string, only when the manifest's ASCII numeric `appid` agrees with its `appmanifest_<id>.acf` filename. Missing, malformed, zero, overflow, or mismatching IDs retain normal game classification but do not enable View in Steam. `path` always opens a scanned folder. If only part of a game was selected, it points to that selected root and its size describes only the scanned portion; `installationPath` retains the true game root. Multiple selected portions appear as separate clickable rows.

Warnings are strings; the first 100 are retained and `warningCount`/status `errors` count the total. During scanning and after cancellation, all totals describe the portion actually enumerated. Export uses an iterative hierarchy writer for deep folders, while the compact file nodes avoid storing a separate full path for every file. The complete hierarchy is still held in RAM; scans with millions of entries can require substantial memory.

Explicit actions require exact membership in the current inventory and check that the item and its scanned ancestors remain available and have not become reparse points. Rename and recycle are disabled during a running scan (409); drive and selected scan roots are protected (403). Rename accepts only a Windows basename, rejects reserved names, separators, invalid characters, trailing dots/spaces, and collisions. It updates descendant paths, registered game paths, extension/category statistics, and ancestor totals in memory. Recycle validates the entire selection before native operations, removes case duplicates and children already covered by a selected folder, and reports individual native failures. A successful rename or recycle batch increments `revision`; clear browser caches or key them by scan ID plus revision. External filesystem changes still require a fresh scan.

Saved libraries appear in `overview.gameLibraries` as an array of absolute folder paths. `/api/game-library` is unavailable while a scan runs and rejects files or paths outside the inventory. Each immediate child directory is a `Custom game library` game, including empty folders. Game rows also include `libraryPath` when they belong to an active custom library, including rows whose launcher metadata is retained. Loose files directly inside the library keep their prior categories. Existing launcher metadata at an identical game path takes priority. Nested or overlapping library declarations, or a proposed game root overlapping a different recognized game root, return 409 to avoid counting the same bytes twice. A later scan that discovers a new conflict suspends that library with a warning and lists it in `inactiveGameLibraries`; its saved mark remains removable. Marking and unmarking update category totals and increment revision without rescanning or changing byte/file/folder totals. Settings are kept in app-local `game-libraries.json`; an explicitly requested test port uses `game-libraries-PORT.json`. Personal settings are excluded from portable releases. Future scans apply saved choices even when scanning only a portion of a game.

View in Steam accepts an exact scanned file or folder path, resolves its nearest recognized Steam installation ancestor, and generates only `steam://nav/games/details/<validated-id>`. It rejects caller-supplied URLs, application IDs, extra body fields, unrecognized games, and paths outside the current inventory. The ID comes from discovered manifest metadata, never from the request. Opening a Steam library page does not change inventory or increment revision; Windows or Steam may report a native protocol association error. The route mirrors Valve's installed client View in Library action.

Recycle-only operations require Windows 8 or newer and local fixed drives. They use `IFileOperation` with `FOFX_RECYCLEONDELETE`, early failure, no elevation prompts, and no connected companion actions. The progress sink vetoes a delete lacking `TSF_DELETE_RECYCLE_IF_POSSIBLE`, and accepts success only when Windows returns a non-null item representing its Recycle Bin destination. Unsupported or unavailable recycling fails without a permanent-delete fallback. See Microsoft's [operation flags](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags), [pre-delete callback](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperationprogresssink-predeleteitem), and [post-delete confirmation](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperationprogresssink-postdeleteitem). Open uses OS file associations but blocks executable/script/installer/shortcut extensions including EXE, BAT/CMD, PS1, JS/VBS, MSI/MSIX, LNK and URL; those items remain available in File Explorer. Native Shell actions can fail on paths or items unsupported by Windows Shell, even when scan enumeration succeeds.

Rebuild with `backend/build.ps1` while `FileGazer.exe` is stopped. It compiles `backend/StorageAtlas.cs` with the Windows Framework compiler into `FileGazer.exe`, referencing only bundled framework assemblies. It also embeds `ui/file-gazer.ico` as the executable's Windows icon and the managed resource `FileGazer.Icon`; the tray clones its own icon from that resource, so it does not depend on the asset file remaining accessible at runtime. No additional runtime or administrative setup is needed. Restart the app after rebuilding, and start a fresh scan.

`backend/verify-extra.ps1` verifies extended-length file paths, overlapping-root deduplication, exact leaf bytes, drilldown/search/export, cross-origin request rejection, and repeated-launch reuse. It scans only its temporary fixture and cleans it afterward. Use the dedicated fixture-only service on port 47841; fixture verifiers replace only that service's in-memory inventory.

`backend/verify-actions.ps1` runs only against the dedicated port 47841, creates its own fixture, and verifies native rename/recycle and inventory updates. Recycled fixture items remain recoverable in the Windows Recycle Bin; retained fixtures are excluded from distribution. Never run fixture verifiers against an inventory you want to preserve.

`backend/verify-steam.ps1` verifies Steam manifest metadata, partial-root recognition, library endpoint guards, and unchanged aggregate bytes against a separate fixture-only test service on port 47841, then moves only its own fixture to the Recycle Bin and stops that service. Its test executable is compiled with `FILEGAZER_STEAM_TEST`, which suppresses only the native Steam protocol launch; the production candidate is compiled separately without that symbol. The verifier never launches real Steam or replaces the normal service inventory. Exclude `backend/steam-tests` and `backend/candidate` from distribution after copying the production candidate into the normal app directory.
